# The relay

**2026-09-13.** While anyone has a record open, its body is one live
document, held in a relay of ours and joined by every editor of it over a
socket. Keystrokes merge as they happen. The relay saves the body through
the app's own write door, and markdown in the brain stays the one truth.

## What it is

`packages/sync`, a Hocuspocus server from npm, run as one process beside
the app. A person's page asks the app for a ticket — which deployment
issued it, who they are, which record, view or edit, an hour — and opens
a socket to the relay with it. The relay verifies the ticket with the
secret it shares with the app, and a view ticket gets a read-only socket.

The relay holds no table. It loads a record from the app that issued the
ticket, in the person's name, and saves through it the same way, so the
brain's two doors stay the only thing that touches the database and one
relay serves every preview at once. It runs the page's own editor
headless, in a small DOM from npm, bound to the shared document: loading
a body and saving it are the exact code the page runs, so what an agent
reads is what a person sees.

## A save per person

The relay saves after a second of quiet, and, before anything from a
different person lands, what the document holds in the name of whose
typing it is. Each save is one person's typing, logged as theirs — not as
an app's — and revert stays one name per change. Every save names the
change it rests on. One that fell behind means the record moved
elsewhere; the relay then takes what the brain has, and the document
follows. It also asks the app every two seconds whether the record
moved, so an agent's rewrite replaces the live text for everyone within
that; typing in the second before it is lost, the trade for not routing
the agent through the relay.

Every minute the relay asks the app whether each person in a document
may still be, at the level their ticket opened, and puts out one who may
not.

## What is refused

The door checks more than the signature: the app is asked, in the
person's name, whether they may still see the record at the level the
ticket opened, so a ticket outlives a share by nothing. And a body the
editor would change — a table, an image, anything it has no node for —
is never made live: the door refuses it, the brain keeps it as it is, and
the page falls back to plain text as it already does alone.

The last person gone, what is pending is saved; if the app will not take
it, the relay tries again for ten seconds, and if it never does, says so
with the text, rather than forgetting it quietly.

## What is thrown away

The live document lives only while someone is in it. When the last
person leaves, the relay saves what is pending and forgets it; the next
arrival rebuilds it from markdown. Storing Yjs's own state would make a
second truth and break export, revert, search and the agent's reads.

So a socket that closes is a document that is over, on the client's side
too: a copy from before, carried into a new socket, would be merged into
the rebuilt document a second time. The client never reconnects with
what it had; whoever wants back in opens anew, from the relay's copy.

## Rejected

Running the relay on the record owner's computer: editing would depend on
somebody else's machine being up, a laptop's app cannot be reached from a
machine, and the field guide keeps the brain and the machine apart.

## Not yet

The page still saves as it did; joining it to the relay, with other
people's cursors, is the next change. The relay runs on Fly, kept up by
the sweep, after that, and only then does production refuse to start
without one: a prerequisite before the thing it requires would stop
production for nothing.
