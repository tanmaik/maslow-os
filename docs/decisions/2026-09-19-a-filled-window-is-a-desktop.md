# A filled window is a desktop of its own

2026-09-19. Tanmai: "Tani wants the green button to actually make it
full screen, to take the full screen, so we have to have some way of
doing that and then bringing it back, and since we have that can we just
have multiple desktops."

## Real full screen

On a laptop the green light, the window's menu and Control-Option-Return
ask the browser for its own full screen as they fill the window, so the
window is the whole display with no browser bar over it. Escape, the
light again and the browser leaving full screen on its own all bring the
window back. Only a hand on this device asks the browser: a window filled
on another device fills this desktop and no more, since a browser gives
full screen to a gesture alone and nobody wants a display taken from
under them. A phone has no full screen to give; there the fill is what it
was.

## Desktops

Every window carries the desktop it is on, a small number, the first when
unsaid, kept with the desktop on the server like the rest of the window.
Which desktop is in view is the device's own, kept in the tab: where a
person is looking is theirs, what they have open is theirs everywhere.
The Window menu lists the desktops in use with the one in view marked,
makes a new one, and Control-Option with the brackets walks them, with D
makes one; a window's own menu moves it to another desktop or a new one.
A desktop nobody is on and nothing is on is not there.

A filled window is a desktop of its own, as a Mac's is: filling moves the
window to a fresh desktop and remembers the one it left; letting it down
brings it back there. A window opened while one fills the screen opens on
the desktop the filled one came from, and that desktop comes into view,
which is how a new window is never behind a filled one, the bug of
2026-09-18. Any number of windows may be filled at once, each on its own.
Widgets lie on every desktop.
