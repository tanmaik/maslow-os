# 2026-09-05 — a record is named by ten characters

Records and edges had uuids. An agent carries every id it reads back into
its context and out again in the next call, and a uuid is thirty-six
characters and around twenty tokens; a page of fifty records with their
edges spent more on names than on content. The web app's addresses were the
same thirty-six characters.

Now `records.id` and `edges.id` are text: ten characters from an alphabet
without i, l, o or u, made by `short_id()` in the database from the random
bits of a uuid, so nothing depends on an extension. Fifty bits is plenty for
one person's brain, and the unique constraint would catch the impossible
collision anyway. Kinds, verbs, fields, grants and everything outside the
brain keep their uuids: nobody passes those around.

The migration renamed every existing row rather than rewriting it: triggers
off, so no version moved and nothing was logged; the log's own copies of
each row renamed with it, so history still points at what it points at.
Every policy and function that read a record's id was dropped and recreated
with the new type, unchanged otherwise.

Considered and rejected: a second short column beside the uuid, which is
two names for one thing; and a prefix of the uuid, which reads as a uuid and
is not unique.
