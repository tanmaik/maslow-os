# Dependencies

Every external dependency, behind the interface of ours it sits behind. Written
when the vendor is added.

| Dependency                           | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Interface                                                   |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| WorkOS                               | Vouches for an email: a six-digit code through its API, behind our own sign-in.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | `deployment.identity`                                       |
| Resend                               | Sends sign-in codes and invitation mail. Required for sign-in in production.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | `deployment.mail`                                           |
| PostHog                              | Product analytics, session replay, error tracking, heatmaps, web vitals and surveys: every page seen, click, error and replay, as the person signed in, in the org they are in, tagged local, preview or production. A person is an id and a role, never a name or an email; a replay masks every input and every word. One project on PostHog's US cloud serves all three deployments (`POSTHOG_KEY`, the project token, which is write-only and made for browsers), and its internal-and-test-users filter keeps only production. The browser reaches it through `/ingest` on our origin, and the full build ships in our bundle so nothing is fetched from PostHog's hosts. Missing outside production, nothing is reported and the pill says so; missing in production, the app does not start.                                                                                                                                                                                                                                                                    | `deployment.analytics`, `apps/web/components/analytics.tsx` |
| Object storage (Tigris, through Fly) | Uploaded images, files on their way to a person's disk, and each disk's daily backups, in a private bucket: production's own, and a second one with its own keys for previews and laptops, so no key outside production reaches production's data. S3-compatible, so the five `STORAGE_*` values and our one signer are all it takes; billed on the Fly invoice, no egress fees. Tigris has no rule to abort stale multipart uploads (our sweep, reap and teardown do that) and answers browser preflights for any origin, so the short-lived presigned URL is the guard. A checkout with none of the five values uses a directory.                                                                                                                                                                                                                                                                                                                                                                                                                                    | `deployment.storage`, `apps/web/lib/s3.ts`                  |
| Fly                                  | Runs computers: one machine with a volume per membership, in one Fly app of ours, through the Machines API with a token scoped to that app (`FLY_API_TOKEN`, `FLY_COMPUTERS_APP`). A wildcard certificate on each app fronts every machine at its own origin, `<machine>.computers.maslow.tech` (production) and `<machine>.computers-preview.maslow.tech` (previews and laptops), records on Vercel DNS; a request naming a machine wakes it, and Fly's proxy suspends it when idle; the image is a whole Debian (node, git, gh, Claude Code, Vercel CLI) copied onto the volume on first boot; the person's home in it is served by the daemon; downloads, the terminal (a shell inside that OS over a WebSocket) and previews of the machine's ports come from the machine itself. Previews get an app of their own with a token scoped to it; their machines and volumes are named for the pull request and destroyed with it, and by the nightly reap. A laptop uses that same app, names its machines `dev-<checkout>-`, and the reap destroys them every night. | `deployment.computers`, `apps/web/lib/fly.ts`               |
| Composio                             | Holds a person's accounts in outside apps: the OAuth apps, the tokens and the refreshing, behind one REST API, using Composio's own managed OAuth apps. The settings page asks Composio for a person's accounts each time it is shown. Ending a membership or deleting an org deletes its accounts there. One project per environment. The free tier covers the MVP. A checkout with no `COMPOSIO_API_KEY` has three pretend apps; production without one has no connections.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | `deployment.connections`, `apps/web/lib/composio.ts`        |
| Neon                                 | The managed Postgres: production's database, and a branch per pull request off an empty parent.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | `DATABASE_URL`, `scripts/preview-db.mjs`                    |
| Vercel                               | Hosting and the environment store. The preview workflow writes a pull request's database URLs there and asks for its one build.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | `scripts/preview-db.mjs`, `pnpm env:pull`                   |
| GitHub Actions                       | Runs `pnpm check` on every push and the preview lifecycle on every pull request event, holding the Neon and Vercel credentials on an environment only `main` can use.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | `.github/workflows`                                         |
| npm registry                         | Everything a checkout installs, the Postgres binary included.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | `pnpm install`                                              |
| node-pty, ws (on the machine)        | The daemon's pty and WebSocket server, in the image. node-pty is native code, compiled in the image's build stage and loaded from its prebuilt binary on a laptop; its install script is on the allow-list for that.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | `apps/computer`                                             |
| @xterm/xterm                         | The terminal in the browser: the one thing on screen beside shadcn, because a terminal emulator is not a component.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | `apps/web/components/terminal.tsx`                          |
| @modelcontextprotocol/sdk            | The MCP wire between the brain and an agent: JSON-RPC over one HTTP endpoint, the tool list, and the schemas an agent reads. Every request stands alone and is answered in one JSON body, so it runs on Vercel. The OAuth in front of it is ours: an app describes itself and carries the description as its client id, and the token it gets is a session.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | `apps/web/lib/mcp.ts`, `apps/web/lib/oauth.ts`              |
