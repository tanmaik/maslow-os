# Dependencies

Every external dependency, behind the interface of ours it sits behind. Written
when the vendor is added.

| Resend                                                                                  | Sends sign-in codes and invitation mail. | PostHog                                                                                 | Product analytics, session replay, error tracking, heatmaps, web vitals and surveys: every page seen, click, error and replay, as the person signed in, in the org they are in, tagged local, preview or production. A person is an id and a role, never a name or an email; a replay masks every input and every word. One project on PostHog's US cloud serves all three deployments (`POSTHOG_KEY`, the project token, which is write-only and made for browsers), and its internal-and-test-users filter keeps only production. The browser reaches it through `/ingest` on our origin, and the full build ships in our bundle so nothing is fetched from PostHog's hosts. Missing outside production, nothing is reported and the pill says so; missing in production, the app does not start.                                                                                                                                                                                                                                                                                  | `deployment.analytics`, `apps/web/components/analytics.tsx`                                                                 |
| Object storage (Tigris, through Fly)                                                    | Profile photos, org logos and the wallpapers a person adds, in a private bucket: production's own (`maslow-uploads`), and a second one with its own keys for previews and laptops (`maslow-uploads-dev`), so no key outside production reaches production's data. S3-compatible, so the five `STORAGE_*` values and our one signer are all it takes; a wallpaper, which is bigger than a function's body takes, goes straight from the browser to an address we sign for exactly its size; billed on the Fly invoice, no egress fees. Tigris has no rule to abort stale multipart uploads (our reap and teardown do that) and answers browser preflights for any origin. A checkout with none of the five values uses a directory.                                                                                                                                                                                                                                                                                                                                                   | `deployment.storage`, `apps/web/lib/s3.ts`                                                                                  |
| Composio                                                                                | Holds a person's accounts in outside apps, several in one app if they like, each with the name they gave it: the OAuth apps, the tokens and the refreshing, behind one REST API, using Composio's own managed OAuth apps. The settings page asks Composio for a person's accounts each time it is shown. Ending a membership or deleting an org deletes its accounts there. One project per environment. The free tier covers the MVP. A checkout with no `COMPOSIO_API_KEY` has three pretend apps; production without one has no connections.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | `deployment.connections`, `apps/web/lib/composio.ts`                                                                        |
| Fly                                                                                     | Runs the computers and the relay for live editing, one small machine per environment kept by the sweep: a machine with a volume per membership, from the image in `apps/computer`, in one Fly app for production and one for previews and laptops (`maslow-computers`, `maslow-computers-dev`). The image is built on Fly's builders with the owner's own login (`fly deploy --build-only --push --remote-only`, from `apps/computer`) and never on a laptop. The app makes machines through the Machines API with one org-wide token (`FLY_API_TOKEN`, `FLY_COMPUTERS_APP`): in the dev secrets, on Vercel's preview and production, and on the GitHub `preview-db` environment for the hourly reap. Every machine is tagged with its environment, org, member and computer, and outside production with its checkout and lease. The page reads each machine's numbers, CPU, memory, bytes used and open ports, from its door, asked with a ticket the machine's secret signs; nothing on the machine calls us. Billed on the same invoice as the bucket.                           | `deployment.computers`, `Cloud` in `apps/web/lib/clouds.ts`, implemented by `apps/web/lib/clouds/fly.ts`; `scripts/fly.mjs` |
| node-pty, tmux (on the machine)                                                         | The terminal behind the Talk socket: `node-pty`, from npm under `/opt/maslow`, compiled when the image is built, gives the door a real terminal to join the socket to; `tmux`, Debian's, holds the session the terminal attaches to, so it outlives every tab. The door starts it inside the person's Linux as the person, a plain shell in its first window; ours sets its colours, mouse and scrollback in `/etc/tmux.conf`, and the person's own file comes after. MIT and ISC.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | `apps/computer/door.mjs`, `apps/computer/etc/tmux.conf`                                                                     |

| Chromium and Xvfb (via Playwright and Debian, on the machine)                           | The browser tool's own Chromium, the full browser rather than the headless shell, fetched from Playwright's store when the image is built, never from the person's disk; with what it needs from Debian. | sharp, ffmpeg, poppler-utils, LibreOffice (on the machine)                              | What turns a file into a small picture for the Files window, all on the person's own machine and never on ours: `sharp` scales a photo, `@ffmpeg-installer/ffmpeg` takes a frame a second into a video, `pdftoppm` (Debian's `poppler-utils`) draws a PDF's first page, and LibreOffice turns a document, spreadsheet or deck into a PDF first. The same ffmpeg, which carries libx264, is the encoder behind the View socket: the browser's pictures in, H.264 out, one fresh encoder per viewer. LibreOffice is unpacked under `/opt/maslow/office` rather than installed into Debian, so all 389 MB of it is bound in read-only and never copied onto the person's disk; two links, `/usr/lib/libreoffice` and `/etc/libreoffice`, point at it because it reads its own configuration from those fixed places, and its registry files are linked into `/etc/libreoffice/registry` from the hidden `share/.registry` folder Debian ships them in, as installing the package would have done.
